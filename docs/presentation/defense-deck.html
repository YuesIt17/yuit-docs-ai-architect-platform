GOALS02 / 16

Why a platform

What the platform solves

Find the rule. Check the source. Keep confidential data closed.

Problem

RISK
Answers not grounded in documents HIGH
Policies, regulations and labels are scattered, so a model can state a requirement that no source contains. Summary quality is assessed separately from ACL.
Confidential promo/margin HIGH
An employee without clearance must not see the secret playbook in an answer or in the source list.
External cloud model BLOCK
Sending internal documents to an external API is unacceptable for this scenario. Local serving is required.

Solution

RESPONSE
Search by relations and fragments GRAPH+VEC
First the product → allergen → rule relations, then text fragments of documents. Each answer comes with sources.
Access filter before the model ACL
The role limits which documents are available. Check the answer and citations, not just the allow/deny badge.
Local model OLLAMA
The demo runs Ollama on CPU. Self-hosted inference does not prove a full network air gap; isolation is verified separately.

COMPONENTS03 / 16

What it is made of

What the platform is made of

REQUEST CONTROL
LangGraph + access checks
Defines processing steps and conditional transitions. Input/output checks and the available-document filter run before answer generation.
RELATIONS
Neo4j
Stores domain relations: product, allergen, rule. Helps find the right documents through the structure of the knowledge.
TEXT FRAGMENTS
Qdrant
Searches document text chunks among the sources already available to the role.
ANSWER
Local model (Ollama)
Writes the answer from the assembled context. The demo uses qwen2.5:0.5b. The vLLM+AWQ submission profile has not been verified on a GPU.
OBSERVABILITY
Grafana + Prometheus + Tempo
Prometheus scrapes metrics from HTTP /metrics (~15 s). Traces: OTLP → Tempo. Logs take a separate path to Loki.
SECONDARY
Redis · MinIO
A cache of finished answers (role-aware) and an object store for files/exports. Not the center of the demo.

Control Plane: API + LangGraph + checks. Data Plane: stores and model serving. Placement is on the next slide.

KP Overview · traffic

Is the API up and how long does an answer take

UP = /metrics scrape succeeded · Requests/min = application paths · RAG latency p50/p95 (quantile 0.95)

UP does not guarantee model answer quality. Latency includes generation if the LLM was called. The status in counters is an application status (allow / stream / cache), not an HTTP code.
